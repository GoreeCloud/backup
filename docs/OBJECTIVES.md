# GoreeCloud Backup — Objectives

Build a privacy-first, self-hosted system for safe backup, verification and recovery, governed by the GoreeCloud four pillars and mandatory Identity.

## Product outcomes

1. Encrypted, deduplicated, versioned backups with a verified end-to-end restore path.
2. Portable local, NAS, S3-compatible and eligible third-party cloud destinations with no forced vendor account.
3. Accessible first-party React web and native Jetpack Compose Android experiences, with honest capability boundaries.
4. Reliable background schedules, retention, integrity checks, observability and recovery drills.
5. Minimum data collection, explicit consent and audited authorization boundaries.

## Measurable acceptance for a future stable release

- Representative backups and restores succeed across file types, sizes, symlinks and permission cases in independent test repositories.
- All configured storage destinations undergo corruption, interrupted-transfer and restore testing.
- Default network exposure and credential handling pass security review; identity, privacy and integration controls are documented and verified.
- Web/Android build and functional tests pass, with supported installation/signing and accessibility verification.
- Repository documentation, licensing, maintenance and branch protections are current and verified.

These are requirements, **not** claims of existing runtime support.
